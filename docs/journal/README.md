# Development journal

The chronological record of how Thought Orchard was made (spec section 24).

## What belongs here

- One file per entry, named by date: `YYYY-MM-DD-short-title.md`.
- The original **Day 1** entry and the messages that informed it.
- Milestones: setup, first run, repository creation, first commit, each phase.
- Decisions, rejected approaches, mistakes, and open questions, in the author's own voice.

## Diagrams

Original UML groundwork (class, sequence, state diagrams) goes in `diagrams/`. Add updated diagrams beside the originals; never overwrite them.

## Rules

- Entries are authentic and chronological. Do not polish them into promotional copy.
- Never edit a past entry to match later decisions. Write a new entry instead.
- Agents may add short factual entries, clearly marked as such, but must not invent history.
- Product requirements live in `docs/spec.md`; architectural decisions in `docs/decisions.md`; shipped changes in `CHANGELOG.md`.
